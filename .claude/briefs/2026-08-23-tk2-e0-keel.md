## QM rulings for this epic (design is settled — do not re-decide)

- **Everything lives under `tokeniko-tk2/`** — you touch NOTHING outside it. Layout:
  `tokeniko-tk2/tk2/` = the installable package (subpackages: `core/` models+constants, `datatier/`)
  · `tokeniko-tk2/db/` = migrations (numbered python scripts) · `tokeniko-tk2/tools/` = runnable
  utilities · `pyproject.toml` at `tokeniko-tk2/` (package `tk2`, taskipy task `body`).
  (plan.md says "lib/"; the QM ruling is `tk2/` for an import name that can never collide with tk1's
  `lib` — record nothing, the plan will be reconciled by the QM.)
- **Db**: the running tk2 body uses sandbox db **`tokeniko_tk2_body`** (MONGO_URI from
  `tokeniko/.env`, same host as the instruments). The GUARD is standard equipment: the datatier
  refuses the tk1 body dbs (`tokeniko`, `tokeniko_mem`, and any name not explicitly whitelisted).
  The experiments db `tokeniko_tk2` stays the instruments'; the body never writes it.
- **Stack**: python + pydantic + bunnet + pymongo + numpy + taskipy + python-dotenv (admitted 2026-08-23) ONLY (stack reqs). No new
  dependency without a STOP-and-report.
- **Write-classes**: every collection model declares its class — `kb` (rw) · `param` (r) ·
  `logic` (r) — as a model-level attribute the datatier enforces (a `param`/`logic` collection has
  no public write path; migrations are the only writer).

## The tasks (one at a time, stop after each)

**T1 — repo scaffold.** `tokeniko-tk2/` package skeleton per the ruling above; pyproject
(editable-installable, `task body` runs a stub `tk2.body` main that logs one tick and exits clean);
a `README.md` at `tokeniko-tk2/` naming the project, the docs, and the sandbox db. Verify:
`pip install -e .` + `task body` run clean.

**T2 — the write-class schema.** `tk2/core/`: the base document conventions — every model carries
its write-class; pydantic is the single source of shape (data-modeling 4, 6); provenance and
epoch-stamp field conventions defined once (mixins), used by all later models.

**T3 — datatier core.** `tk2/datatier/`: mongo client + the GUARD (refuses non-whitelisted dbs);
bunnet init wrapping the tk1 traps away (a `fetch()` that always `.run()`s; timeseries delete via
raw pymongo, exposed as one honest function); the **r-cache**: `param`/`logic` collections loaded
at boot into an in-memory snapshot + a slow-tick refresh (interval itself a param row, default 60s).

**T4 — new-organ collections, shaped empty.** Models + registration for: heart_levels · heart_mood ·
heart_temperament · heart_targets (per-uid) · emotional_log · forecasts (confidence + future
spacetime) · derived_points (epoch-stamped) · micro_nn_instances (config + weights + epoch) ·
channel_registers · params (the r-class parameter store). Shapes follow the requirements files —
fields minimal but honest (no speculative columns).

**T5 — migration runner.** `tokeniko-tk2/db/`: numbered migrations, applied-state recorded in a
`migrations` collection; `tools/migrate.py` runs pending ones. **Migration 0001 creates the world**:
the collections above + the seed param rows (slow-tick interval, budget caps placeholder). Then the
E0 gate: `task body` boots, r-cache loads from rows, ticks; you edit one param row via a second
migration (0002), and the running body picks it up on the slow tick WITHOUT restart — capture the
log proving it.
