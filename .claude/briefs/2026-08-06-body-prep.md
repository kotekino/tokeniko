## Item 1 — `scripts/body/run_service.sh` (the wait-for-Mongo wrapper)

**Why it exists:** launchd has **no dependency ordering**, and `init_io()` dies if Mongo is not yet
up. This wrapper is what makes an unattended boot deterministic.

- Usage: `run_service.sh api|brain|senses`. Reject anything else with a usage message + non-zero exit.
- Resolve its own directory so it works regardless of cwd; `cd` to the **package dir**.
- Source `.env` from the package dir (handle values containing `=` and `#`; do not export comments).
  If `.env` is missing → fail loudly with a clear message.
- **Poll Mongo until it answers**, then `exec` the service:
  - use `../.venv/bin/python` with **pymongo** (already a dependency) to ping — **do not** depend on
    `mongosh` being installed on the mini;
  - use `MONGO_URI` from `.env`, a short per-attempt `serverSelectionTimeoutMS`, a sleep between
    attempts, and a bounded total wait (make it a constant near the top, ~5 minutes) — on timeout,
    log clearly and exit non-zero so **launchd's `KeepAlive` retries** rather than the script hanging forever;
  - log each attempt sparsely (first, then every Nth) so a months-long log doesn't fill with noise.
- Then `exec` (so launchd supervises the real process, not a shell):
  - `api` → `../.venv/bin/uvicorn api.main:app --host 0.0.0.0 --port 8000 --workers 1`
    — **no `--reload`** (it is a file-watcher restarting the mind) and **exactly one worker**
    (`app.state` holds the loaded parser + service singletons; two workers diverge). Runbook §0 + §2.7.
  - `brain` → `../.venv/bin/python -m brain.main`
  - `senses` → `../.venv/bin/python -m senses.main`
- `set -euo pipefail`, `chmod +x`.

     (The Mind Monitor on tokeniko.online is the human-eye check — mention it in the output, don't script it.)
- Support `--dry-run` printing every remote command without executing — that is how the Captain will

## Item 4 — `scripts/body/verify_transplant.py` (the QM's addition — runbook §3.5, scripted)

**Why:** §3.5 says "verify before deleting anything" but is written as a manual eyeball check, and
"counts match" is otherwise checked against human memory. This turns the one irreversible-feeling
step into arithmetic: **capture the baseline on the MacBook today, run the same probe on the mini
after the copy, diff the two.**

**Read-only. It must be incapable of writing** — no inserts, no updates, no index creation. Say so
in the module docstring.

- CLI: `verify_transplant.py [--uri <MONGO_URI>] [--out baseline.json] [--compare baseline.json] [--fast]`
  - default `--uri` from `.env` (`MONGO_URI`), so it runs bare on either machine
  - `--out` writes the snapshot as JSON; `--compare` diffs the live snapshot against a saved one
  - `--fast` uses estimated counts; **exact counts are the default** (this is a verification tool)
- The snapshot, per database (`MONGO_DB_NAME`, `MONGO_DB_NAME_MEMORY`, and the sandbox DB name read
  from `tests/conftest.py`):
  - every collection with its **document count**
  - the **search indexes** present, if the server will list them (`listSearchIndexes`) — that is the
    `mongot` metadata whose survival is the real risk of the move
- Plus three targeted probes:
  1. **`$vectorSearch` answers** — the truest proof `mongot` survived. Make it **self-proving**:
     fetch one dictionary row, use *its own* `vector` as the query vector, and assert the nearest
     result is that same word with a score at ~1.0. Reuse `_VECTOR_INDEX` from `lib/core/models.py`
     and the pipeline shape at `lib/llc/evaluator/e_label.py:76-90` — do not invent your own.
  2. **`brain_state`** — the birth stamp (**must read 2026-07-09 06:21:37Z**) plus the continuity
     fields that exist on the singleton (read the model; report them, don't guess names).
  3. **The memory timeseries** — document count + the **latest timestamp** (field name from
     `lib/core/models.py`), proving the record reaches the present.
- Output: a readable table to stdout AND the JSON. In `--compare` mode print a per-row
  `baseline → live` diff, and **exit non-zero on any mismatch** so it can gate the deletion step.
- Handle a **missing database or collection** gracefully (report as absent, don't crash) — on the
  mini, before the copy, everything is absent, and that is a legitimate run.

**Then run it for real, here, now**: capture the baseline to
`scripts/body/baseline-macbook-2026-08-06.json` and **commit-stage it as part of your deliverable**
(the QM commits it — it is evidence, and it must exist in git before the move). Read-only, so it is
safe against the live body. Paste the human-readable table into your report.
