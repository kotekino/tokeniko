# evaluator — REQUIREMENTS

*What the evaluator must be. One line each. Evidence lives in the dated `_notes.md` beside this.*

1. **A pure function** — stores nothing, believes nothing; the evaluator judges, the brain admits.
2. **One verdict shape for every caller** — truth in [0,1] · status (proven / refuted / insufficient / INCONSISTENT) · bindings (every solved variable, senses included) · derivation (the premise chain, always).
3. **The one mandatory rung** — every input reaches it, self-talk included (brain req. 6); it is the KB's door.
4. **INCONSISTENT is reserved for logic alone** — the hardwired form check runs first; KB-refutation is refuted, never inconsistent.
5. **One algorithm, no WSD stage** — sense slots, wh-gaps, unbound roles are the same problem: try bindings, keep the one whose grounding survives the KB (tkzip #10 generalized).
6. **Every grounding is a dual read** — stated cell + cosine, at both floors, and the derivation names the source.
7. **Chaining fires when direct grounding is silent** — corroborate or KB-refute, premises in the chain.
8. **ABSTAIN is first-class at every depth** — never guess; where nothing proves, insufficient.
9. **The search is budgeted** — depth/time caps are db(r) parameters; budget-out returns insufficient WITH the depth stamped — honest, never false.
10. **Instinct may ORDER the search, never the verdict** — micro-nn ranks which binding to try first; accept/reject stays deterministic math (truth sacred, choice free).
11. **Deterministic** — same KB, same zip, same verdict; no noise inside (brain req. 13).
12. **Stake resolution is the evaluator's** — arriving events are matched against staked forecasts; «came true / broke» is the verdict that fires serendipity or disillusion (heart reqs 8, 17).
