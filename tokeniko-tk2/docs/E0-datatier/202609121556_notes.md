## THE RETREAT CASCADE HAS NO REVERSE INDEX

E0's `Parent` model (`tk2/core/mixins.py`) says:

> *«A bare id would be ambiguous the moment two collections hold one — and the retreat cascade has to
> be able to FOLLOW this reference, not merely record that something existed.»*

`Parent` is `{collection, id}` stored on the child. So **child → parent** is a direct lookup and works
exactly as the docstring intends.

**But the cascade runs the other way.** When a belief falls, the question is *«what was built on
it?»* — **parent → children** — and that is a search for every row whose `parents` array contains
this id, across every KB collection. **`parents.id` is indexed nowhere.** Today that is a full scan
per retreat, on every KB collection, and retreat is not rare: it is one of the five inner actions
(brain req 2) and it fires on every contradiction the evaluator finds.

**Why it is cheapest to fix now:** it is a multikey index on an existing field, it changes no model
and no caller, and the alternative is discovering it as a performance problem at E6 when the brain
loop is already the thing under test. It also belongs here rather than in the models: requirement 6
says the tier is readers, writers, caches and guards — an access-path decision is exactly that.

**Not decided here:** whether the reverse walk is one indexed query per collection, a dedicated edge
collection, or a cached graph. That is this chapter's call when it opens; only the gap is recorded.
