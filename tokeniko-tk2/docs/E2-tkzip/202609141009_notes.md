## THE THREE FORCED CHANGES

The guard exists because an instrument that can always be satisfied by moving the target measures
nothing. Each is named with the sentence that forced it, and the COUNT is part of the result.

### #1 — `direction`, the eighteenth role

> «He looked **up**.» · «She turned **left**.»

A direction with **no endpoint**. Not a `destination` (he does not arrive at *up*), not a `path` (it
is not a route), not a `manner`. The marker could not rescue it because there was no box to mark.

The cluster was aimed at «to / toward», and **those were fine** — req 65's marker distinguishes them
exactly as intended. The gap was one step further out, and two witnesses with two different verbs
found it. PropBank keeps `ARGM-DIR` separate (1,419 uses) and FrameNet has Direction beside Path and
Goal: the first cut had source, path and destination and simply missed the fourth.

**This is the Captain's own prediction from task 1 coming true**: *«a miss is a bug, found by the
instruments, fixed by redesigning the frame»* — not a migration.

### #2 — `scopes`: a prefix element names the matrix it applies to

> «software **can** be minds and humans **must** be minds»   *(his traffic, `missed-modality`)*

`◇A ∧ □B` — two different modalities over two conjuncts. A prefix element scoping «everything after
it» **cannot express this**: put ◇ first and it swallows B as well. The same shape breaks for
attitudes («Anna thinks X and Bob thinks Y») and domains («legally P but actually Q»).

Because a named row may itself be a JOIN covering a whole subtree, naming the target gives arbitrary
nesting for free — the Tseitin machinery paying for itself a second time.

**And it tightened the design rather than loosening it.** With `scopes` free to name any row, `¬∀`
would have had two spellings — chained pointers, or sibling order. So: **`scopes` names a MATRIX
(a content or join row) and never another prefix row.** Nesting among prefix elements is their ORDER,
and `scopes` only says which matrix they nest over. Row order = scope order survives intact, and a
validator enforces it.

### #3 — `Ref`: a box may hold a row name

> «Cognition is the psychological result **of perception and learning and reasoning**.»

The `relation` of *result* is a three-way coordination — a **join row**, not a word. Requirement 34
already said a box may hold a row name; there was simply **no type for it**, so the name validated as
a bare `BaseKey` and the evaluator would have gone looking for «j2» in the dictionary. The mildest
kind of forced change: an omission against a requirement already made.

## WHAT THE SIX CLUSTERS DECIDED

| cluster | verdict |
|---|---|
| **«only»** | **collapses — no sixth prefix element.** Six sentences, all encoded with the operator set plus binder restrictions. «Only smoking causes cancer» is `CONV`; «smoking only causes cancer» is a universal over effects. *`CONV` surviving task 2 turned out to be load-bearing here.* |
| **«to / toward»** | the marker is enough — but the cluster found `direction` one step out (forced change #1) |
| **existential `be`** | content, confirmed. A binder alone is not a claim (binders are not claimable), so existence **must** be asserted by a content row |
| **`never` · `hardly` · `almost`** | **req 23 OVER-GROUPED — see below** |
| **«twice a week»** | **`count` holds it.** The binder carries `count=2` and its restriction the universal over weeks: ∀week ∃²occasion. Strained but expressible; `frequency` stays structure, as req 32's least-confident ruling hoped |
| **de re / de dicto** | the prefix expresses both, as α claimed |

### The amendment: req 23 over-grouped three words

It put *never*, *hardly* and *almost* together as «structure, not description». The drill separates
them:

- **`never`** → negation + a universal over the time variable, both in the prefix. Collapses exactly
  as ruled.
- **`hardly`** → a manner box carrying **only a degree** — «works, to a small degree». Not structure
  in the way `never` is.
- **`almost`** → **neither, and it is the drill's only abstention.** «He almost died» asserts he did
  NOT die AND that the event was close; closeness-to-an-event-that-did-not-happen has no home.
  Honestly partial — unplaced material, confidence 0.6 — rather than silently dropped.

Two witnesses (`almost died`, `almost finished`), two different verbs and aspects.

## THE DRILL CAUGHT THE QM, NOT ONLY THE SCHEMA

Auditing the encodings before scoring — because the same hand wrote the schema and the drill —
**seven were wrong**, and none of them was the schema's fault:

| what | the error |
|---|---|
| «a **human** body» | the adjective was put in `relation`, which is the **possessor** slot |
| «a **big** city» | encoded as a `degree`; `degree` is for «*very* big», an intensifier on a property |
| «a **foreign** licence» | simply dropped |
| «smoking causes cancer» ×3 | bare nominalisations instead of propositions over a person variable |

**The correction needed no new field: ATTRIBUTIVE ADJECTIVES ARE SECOND ROWS.** «A human body» is
∃B(body(B) ∧ human(B)) — a binder and a co-asserted content row, which is the same machinery as the
depictive «he ate the fish raw». The cost is row inflation, which sparse storage absorbs at ~250
bytes a row.

**A second division the drill settled at no cost:** single-row negation is **`truth = 0.0`**, claimed
false. `NegationRow` is for negation that must scope OVER another prefix element — `¬∀` versus `∀¬` —
which is the only case where the order matters. «I'm not a software but I am a mind» settled it.
