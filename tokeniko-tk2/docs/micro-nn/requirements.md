# micro-nn — REQUIREMENTS

*What the instinct framework must be. One line each. Evidence in the dated `_notes.md` beside this.*

1. **One abstraction, many instances** — a single middleware serves every use case; instances differ by declaration (input schema · output kind · reward source), never by stack. **[WHERE IT IS BUILT, ruled 2026-09-16 — the abstraction lands in E3b, not in this chapter's own epic: *«E5 remains where it is, but the machinery should go in E3b»* (the Captain), because name resolution cannot close without a net. Reqs 1–4, 7 and 8 are therefore E3b's to satisfy and E5 keeps the breadth and the reward plumbing. The reason is not scheduling: a framework generalized BEFORE it has met a real case is the failure this requirement is most exposed to, and its first case now arrives with it.]**
2. **One shape** — features in → a ranking or a scalar in [0,1] out; nothing else.
3. **Tiny and laptop-honest** — small nets, numpy-scale; no heavyweight framework.
4. **Weights are db rows, epoch-stamped** — an instance is config + weights in the db; training moves rows, never code.
5. **Learned online from the reward families** — intellectual + heart (brain req. 18); positive feedback loops.
6. **The six sites**: evaluator search order · brain thresholds · the heart jump (attention bias) · the figurative layer · the channel register · the mouth's coloring. **[EXTENDED — the station's confidence calibration is the seventh (parser-compiler req 5), and NAME RESOLUTION is the eighth and arrives FIRST (parser-compiler req 16, E3b): which «Paris» a stranger means, ranked among the candidates a curated table already produced. It is the first site admitted by req 9 rather than declared at conception.]**
7. **The shared fence** — ranks among already-legal options ONLY: never a verdict, never content, no provenance ⇒ never a belief; a kb rule outranks it, always.
8. **Deterministic per weights-version** — same features, same epoch, same output; variability enters by learning, not by noise.
9. **WHEN a micro-nn is admitted at all** *(the Captain, 2026-09-16)* — **exactly where curation is not entirely possible, and where the decision can change over time.** Both clauses, and in that order: curation is tried FIRST and a net is admitted only where curation demonstrably cannot finish. The project has already run both tests by hand — a closed class can be enumerated completely, so it is a table (`db/0008`); UD's 37 relations can be enumerated, so the gate can be complete; «which Paris did he mean» can be curated for the places we have seen and never for the next one, **and the answer moves**, because what is prominent this year was not prominent last year. That is the first case to pass both tests. The consequence for a builder: the net's job is to RANK what the curation produced, never to replace it — which is req 7's fence arriving from the other direction.
