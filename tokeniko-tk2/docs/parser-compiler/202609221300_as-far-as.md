## THE ROADMAP SAID «A CURATION ROW». IT WAS THAT AND ONE MORE THING

**The row was genuinely missing.** `db/0015` names this exact phrase in the ruling that created
`destination`:

    dir-1  I walk to the station          destination = station.n, marker «to»
    dir-2  I walk toward the station      destination = station.n, marker «toward»
    dir-3  I walked as far as the bridge  destination = bridge.n, marker «as far as»

and the table already held `as for` · `as from` · `as of` · `as to` · `as if` · `as long as` ·
`as soon as` · `as though` · `up to`. «as far as» was the one gap in a complete family. Without it
the bare `as` answered — `roles: [manner, measure]` — so «as far as the station» read the station
as a MEASURE.

**AND ADDING IT ALONE MADE THINGS WORSE.** With the row in, both tenses lost the noun where before
only the past tense did. The multi-word match is longest-first, so it consumed the very `as` that
had been doing the work — and the nominal was left with no marker at all.

## stanza READS ONE PHRASE TWO WAYS, AND THE TENSE DECIDES WHICH

    « I walk as far as the station. »    the 2nd `as` is `case`  -> station   (an ordinary child)
    « I walked as far as the bridge. »   the 2nd `as` is `fixed` -> the 1st `as`

In the past tense the bridge hangs off `far` — a token **inside** the marker — and has no `case`
child, so `_marker_role` and `_box_for`, which both walked the nominal's CHILDREN, could not see the
marker that was right there. Same phrase, same meaning, different tree, and the defect was
tense-dependent for that reason alone.

**Reading the marker's SPAN holds under either analysis**: a multi-word marker whose span contains
the nominal's own head is that nominal's marker. That is the tree's own shape, which is frame — and
it is narrow on purpose. Only a multi-word marker can swallow a head, and only the head: a nominal
that merely sits near a marker is not marked by it.

recorded on the box, which is where req 65 puts «no arrival entailed». Getting the role right and
losing the marker would have put the entailment in the role, the one place `db/0015` says it must
