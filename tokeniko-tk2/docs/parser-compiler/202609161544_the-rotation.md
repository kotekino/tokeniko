## THE RULING, AND WHY (b) WAS THE WRONG SAVING

Two ways to know who «you» is inside «John said TO MARIE: …»:

**(a) `Pov` and `AttitudeRow` gain an `addressee`.** Explicit, and a **schema change on a format
frozen at v2** — req 73: *«every change from here is a migration under the Captain's hand, never an
edit»*.

**(b) The resolver reads the `recipient` box of a `say` row.** No format change at all — and it asks
the resolver to **know that saying-verbs are special**, which is a closed set of verbs in code. That
is the exact shape the Captain's own rule of this morning refuses, and two days of this epic have
been spent moving such sets into rows.

**He ruled (a), and the cost was smaller than the principle.** `SCHEMA_VERSION = 3`, one field on two
classes, and **the body holds zero zips** — `tkzip_derived_points` is empty — so E9's translation
night has nothing to translate. *The first migration of the frozen schema, and it bought the one
thing (b) could not: the format can SAY who an attitude addressed.*

**EMPTY IS THE POINT, NOT `Open()`.** `addressee: Box | None = None`, and the difference is
load-bearing: **«no addressee» and «addressed to somebody unknown» are different facts**, and only
the first stops a rotation. Thinking addresses nobody.

## THE RULE, WORKING

    «John said to Marie that YOU swim»   ->  marie.n    the saying's recipient
    «John thinks that I swim»            ->  john.n     the holder; and «you» stays the outer listener
    «if you know who did it»             ->  unchanged  a conditional is not an attitude

**Only an ATTITUDE rotates**, and the test is the joiner saying `asserts: matrix` — «he says THAT
you swim» claims the saying and not the swimming — which is the same test `_relate` already uses to
raise the `AttitudeRow`.

**AND IT HAD TO BE DECIDED BEFORE THE CLAUSES WERE COMPILED.** A pronoun is resolved where it is
met, and the attitude that governs it is built later, in `_relate` — so by the time the POV existed,
the `you` inside it had already been given the outer addressee. The tree says which clause sits under
which attitude and the tree is known first, so the contexts are worked out in a pass of their own.
*The holder and addressee are read from the SKELETON there rather than from the compiled row, because
the rows do not exist yet — a small duplication of `_role_of`'s job, and the honest one: the
alternative is to compile every clause twice.*

## THE CAPTAIN'S OWN SENTENCE CROSSES A SENTENCE BOUNDARY

Stanza splits a quote (2b.2's finding), so «John said to Marie " You are a clever girl "» is **two
skeletons** and the attitude machinery above never sees it. The same rule applies one level up: a
sentence that is a **FRAME** — a saying with an agent and a recipient — rotates the next one.

    r0     say.v  agent = john.n, recipient = marie.n
    s1.r0  patient = marie.n, complement = Var(s1.x0)      ← «You»
    s1.m0  patient = Var(s1.x0), complement = clever.a      ← «clever»

**A frame without a recipient does not rotate.** «John said.» addresses nobody in particular, so
there is nothing for a second person to rotate into and the outer addressee rightly survives.

## THE ONE THING IN CODE THAT SHOULD NOT BE, NAMED ON ARRIVAL

`SAYING_VERBS` — nine keys, in a Python frozenset. **It is on E3's frame/knowledge audit list in the
same commit that introduced it**, and it is a placeholder with a known replacement: req 55 already
rules that *«attitude verbs are open — think, believe, suppose, want, fear, pretend, hope, doubt — so
the classification is nearest-anchor geometry over a small anchor set, and never misses the verb
nobody thought of»*. **E4 owns that geometry.** Until it exists, a nine-word list is the smallest
honest stand-in, and writing it without saying so would have been the defect the Captain's rule
exists to catch.

*The in-sentence path does NOT use it — there the joiner's own `asserts: matrix` row says what is an
attitude, which is curation doing the job properly. The list is only reached across a sentence
boundary, where there is no joiner to ask.*
